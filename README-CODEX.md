# Как пользоваться этой папкой в ChatGPT Codex

Схема теперь максимально простая:

1. Codex сам создаёт Git-репозиторий и весь обязательный проект с нуля.
2. Во время BUILD MODE он сам ведёт Git и делает осмысленные коммиты без подтверждения.
3. После готового проекта ты переходишь в отдельный LEARNING MODE и изучаешь уже существующий код.
4. Перед собеседованием включаешь INTERVIEW MODE.

Ручное руководство разработкой не требуется.

## Первый чат: что написать

Открой **корневую папку** в ChatGPT Codex и отправь:

> Прочитай AGENTS.md и все docs/*.md. Начинай BUILD MODE и автономно доведи всю обязательную часть тестового задания до готового состояния. Проект и Git-репозиторий создавай с нуля сам. Сам веди Git по docs/GIT_RULES.md: делай осмысленные коммиты по завершённым функциональным блокам, не спрашивай у меня подтверждение перед коммитами и не упоминай Codex, OpenAI, ChatGPT или AI в ветках, сообщениях коммитов и Git-метаданных. Сам запускай Docker, миграции и проверки. После завершения обязательной части выполни fresh-run проверку и, если GitHub-аутентификация доступна, сам создай публичный GitHub-репозиторий и запушь main. Во время BUILD MODE меня не обучай. Останавливайся только если реально заблокирован или требуется потенциально разрушительное/необратимое решение.

Этого достаточно. После этого не нужно по очереди просить создать Entity, Controller, Docker и т.д. Последовательность уже задана в `docs/BUILD_PLAN.md`.

## Что Codex должен сделать сам

В начале:

- прочитать правила;
- выполнить `git init -b main`, если `.git` отсутствует;
- использовать твою обычную Git identity, а не bot/tool identity;
- создать Symfony-проект;
- создать Docker-конфигурацию;
- подключить PostgreSQL/Doctrine;
- дальше двигаться по BUILD_PLAN.

После каждого крупного функционального блока он должен:

- проверить изменения;
- посмотреть diff/status;
- сам создать нормальный Conventional Commit;
- обновить `docs/STATE.md`;
- продолжить следующий блок.

Он **не должен** останавливаться после каждого файла или коммита и ждать фразы «коммить».

## Какая история Git ожидается

Не десятки микрокоммитов. Ориентир для обязательной части — примерно 5–8 содержательных коммитов, например:

```text
chore: Bootstrap Symfony application
feat(domain): Add task and status entities
feat(status): Implement status API
feat(task): Implement task API
fix(api): Harden validation and errors
docs: Complete setup and architecture guide
```

Это не фиксированный список. Сообщение должно соответствовать реальному diff.

Правила подробно описаны в `docs/GIT_RULES.md`.

## Что будет с GitHub

Тебе не нужно заранее создавать репозиторий.

Сначала Codex ведёт локальную историю. Когда обязательная часть полностью работает и проходит fresh-run проверку, он должен попытаться сам:

1. создать публичный GitHub-репозиторий через уже авторизованный аккаунт;
2. использовать нейтральное имя `skyeng-task-manager` (или `skyeng-backend-task-manager`, если первое занято);
3. добавить `origin`;
4. запушить `main` с полной историей;
5. сообщить тебе итоговую ссылку.

Если в окружении нет GitHub-аутентификации или инструмента для создания remote, только тогда он должен попросить минимальное действие от тебя.

## Если открыл новый чат во время разработки

Напиши:

> Продолжай BUILD MODE автономно с текущего состояния. Сначала прочитай AGENTS.md, docs/STATE.md и docs/GIT_RULES.md, затем проверь Git и продолжи первый незавершённый batch. Не начинай проект заново и не спрашивай подтверждение перед обычными коммитами.

## Когда BUILD MODE закончен

Он считается законченным только когда:

- реализованы все обязательные endpoints;
- корректно обрабатываются обязательные ошибки/edge cases;
- Docker Compose поднимает приложение и PostgreSQL;
- миграции работают на чистой БД;
- README соответствует реальным командам;
- выполнена fresh-run проверка;
- `docs/STATE.md` отмечает обязательную часть как завершённую;
- Git-история сохранена и не схлопнута;
- при доступной GitHub-аутентификации создан и запушен публичный remote.

## После сборки: начать обучение

Лучше создать новый чат в том же проекте и написать:

> Переключайся в LEARNING MODE. Прочитай AGENTS.md, docs/LEARNING_PLAN.md и docs/LEARNING_STATE.md. Начни с первого незавершённого учебного модуля. Я знаю общие основы программирования, но PHP, Symfony и SQL для меня практически новые. Учи меня именно по готовому проекту.

Здесь уже начинается теория, разбор PHP/Symfony/Doctrine/Docker и вопросы по реальному коду.

## Продолжить обучение в новом чате

> Продолжай LEARNING MODE по docs/LEARNING_STATE.md. Коротко напомни, где мы остановились, и продолжай.

## Провести checkpoint

> Проведи checkpoint по всему уже изученному: теория, вопросы по реальному коду, change-impact вопросы и одна маленькая задача на изменение. Соблюдай правило двух попыток.

## Перед собеседованием

> Включи INTERVIEW MODE и следуй docs/INTERVIEW_MODE.md. Не пиши код за меня. Проведи защиту по реальному репозиторию и потом дай одно небольшое изменение, которое я должен внести сам.

## Что тебе реально нужно запомнить

Для первого запуска достаточно одной команды:

> Прочитай AGENTS.md и все docs/*.md. Начинай BUILD MODE и доведи обязательную часть до конца автономно.

Полный стартовый промпт выше лучше использовать первый раз, потому что он явно фиксирует Git/GitHub-поведение.
